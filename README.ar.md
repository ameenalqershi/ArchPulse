# ArchPulse — آرتش بالس

**منصة الهندسة البرمجية الحية واستشراف المستقبل المعماري** — **مرحلة التأسيس الهندسي، قيد التطوير** — **Apache-2.0**

[English](README.md) · [المساهمة](CONTRIBUTING.md) · [الحوكمة](GOVERNANCE.md) · [خريطة الطريق](ROADMAP.md) · [استمرارية الوكلاء](AGENTS.md)

> **المشروع قيد التطوير التجريبي وليس جاهزًا للإنتاج.** أصبح هناك محرك تحليل Roslyn فعلي ومخزن Graph بإصدارات، وواجهة محلية لقراءة المخططات، ونموذج Web Studio وMCP، وربط ثابت للاختبارات وإيصالات تشغيل محلية جزئية. هذا لا يعني وجود تحليل تشغيل حي أو خدمة ChatGPT عامة مصادق عليها أو اكتمال المواصفات S00–S33.

## الرؤية والمشكلة

يفصل المطور بين الحقيقة الموجودة في الشيفرة، والمعمارية التي قررها المهندس، ومسارات التشغيل التي أثبتتها التليمترية، والاستنتاجات التي قد يقدمها وكيل الذكاء الاصطناعي. يهدف ArchPulse إلى ربط هذه الأدلة بمخطط هندسي حي متدرج من النظام إلى الدالة، يستطيع الإنسان استخدامه للفهم والتوجيه والمراجعة دون خلط المقترح بالواقع.

المخطط المقصود ليس سطحًا واحدًا ضخمًا؛ بل خرائط متداخلة بحسب المجال والوحدة والخدمة والكلاس والدالة، مع مخططات Flow وDataJourney عند الطلب. وتعرض المخالفات المعمارية مع مصدرها وأثرها ولا تخفي التحذيرات عند طي التفاصيل.

## الوحدات المخطط لها

- **Engineering Knowledge Graph وRoslyn:** استخراج علاقات الشيفرة ومراجعها عبر الإصدارات.
- **ArchitectureGuardian:** التحقق من العقود المعمارية وشرح الانحراف بالدليل.
- **FeatureAtlas وDataJourney:** ربط وظائف الأعمال ومسارات البيانات مع ضمانات الخصوصية.
- **Live Observability:** ربط تشغيل النظام بإصدار BuildSHA، لا تخمين الواقع من التحليل الساكن.
- **OpenRepoLab وTest Execution Journey:** ربط الاختبار بالدالة على نفس الرسم وعرض الاستدعاءات والعوائد والاستثناءات والـAssertions وحالة الدليل وإعادة التشغيل.
- **Futures Engine / AET:** مقارنة البدائل الهندسية المعزولة وقياسها ثم إحالة القرار للإنسان.
- **Agent Gateway وCross-Agent Continuity:** تسليم العمل بين الوكلاء من Checkpoints وأدلة وعمليات استرداد آمنة.
- **Web Studio وVS Code وCLI وMCP Apps:** حوار ثنائي الاتجاه بين الرسم والمهندس والوكيل، مع Mermaid لكل بديل معماري.

توجد **أجزاء منفذة ومختبرة محليًا فقط** من Roslyn/Graph وGuardian وWeb Studio وMCP وربط الاختبارات، بالإضافة إلى تعريف ميزات الأعمال يدويًا في [FeatureAtlas](docs/guides/feature-atlas-local.md) (جزء من T023/S05)، واكتشاف إشارات أولية من MVC والـHandlers والاختبارات باستخدام Roslyn (جزء من T024/S05)، مع تصنيف دلالات الأعمال بوصفها **استنتاجات تحتاج مراجعة بشرية** وليست ميزات معتمدة. [دليل الاكتشاف](docs/guides/feature-discovery-local.md). كما أضيف محلل جزئي لأثر التغيّرات البنيوية بين إصدارين من Graph على ميزات أعمال **مرشحة** مع مسار استدعاء ثابت ودون ادعاء أثر PR كامل أو تشغيل فعلي ([الدليل](docs/guides/feature-impact-local.md)، T025/S05). أما اكتشاف ميزات الأعمال آليًا وDataJourney وFutures Engine والتليمترية الفعلية والمنصة الإنتاجية فما زالت غير مكتملة. يجب الاستناد إلى الاختبارات وCI الخاصين بكل Commit، وليس إلى العناوين أو الرسومات المقترحة.

## ما الموجود في حزمة التأسيس؟

يحتوي المشروع الآن على عدة وحدات ‎C#/.NET 10‎ حقيقية: Graph وRoslyn وGuardian وASP.NET Core وCLI وMCP وخدمات التحقق والاختبارات، إضافة إلى واجهة React تجريبية. تُحافظ الوحدات على الفصل بين الأدلة الثابتة والمقترحة والتشغيل المرصود. راجع [دليل CLI](docs/guides/dotnet-native-cli.md)، و[واجهات Graph المحلية](docs/guides/local-graph-api.md)، و[دليل MCP](docs/guides/mcp-apps-local.md).

للبناء يتطلب .NET 10 SDK ثم:

```bash
dotnet restore ArchPulse.sln
dotnet build ArchPulse.sln --no-restore -c Release
dotnet test ArchPulse.sln --no-build -c Release
```

يُنفذ البناء والاختبار فعليًا في بيئة Linux المحلية ويُعاد التحقق في GitHub Actions عند تقديم كل تغيير؛ لا تعتبر الإصدارات مكتملة أو معتمدة قبل مراجعة الدليل على SHA المحدد. يستطيع المطور المساهمة عبر Fork وIssue وPull Request دون اشتراط عضوية رسمية. يوضح [دليل المساهمة](CONTRIBUTING.md) و[الحوكمة](GOVERNANCE.md) طريقة ذلك.
