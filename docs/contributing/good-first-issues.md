# Good first issue criteria

A contribution is suitable when it is well specified, self-contained, safe for a public fork, and has reproducible acceptance checks. Prefer documentation, test fixtures, typed contract examples, accessibility checks and isolated SDK samples. **Not** a good first issue: production sandbox hardening, privilege delegation, agent approvals or safety-critical policy bypasses.

Triage label `good first issue` only after a maintainer reviews the specification and dependencies. Record Txxx and Sxx and a passing verification command in the issue body.
