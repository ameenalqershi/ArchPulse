# Maintainer nomination and permissions

The open-source community is open to contributions without GitHub organization membership. No one receives elevated permissions automatically.

## Selection criteria

A nominee should have sustained technical contributions, adherence to security/privacy rules, evidence-based decisions, clear communication, and reliable reviews. Module maintainers additionally demonstrate bounded-context ownership and ability to guide tests, documentation and compatibility.

## Nomination procedure

1. An existing maintainer opens a private or public nomination discussion as appropriate, with examples of merged contributions and review history. Never publish personal data without consent.
2. The nominee **explicitly accepts** the nomination, scope of responsibility and the code of conduct.
3. The project owner or authorized core maintainers assess conflicts of interest, module coverage, security implications and onboarding needs.
4. Record the decision and agreed scope; grant the minimum GitHub role required. Core/admin privileges require explicit owner authorization.
5. Revisit access periodically, especially after inactivity, conflict or departure; document removals and appeals fairly.

## Role distinctions

Contributor and Regular Contributor require no repository permissions. Reviewer may advise or formally review depending on granted permissions; Module Maintainer maintains a defined area; Core Maintainer manages cross-module policy; Project Owner controls legal and administrative decisions.
