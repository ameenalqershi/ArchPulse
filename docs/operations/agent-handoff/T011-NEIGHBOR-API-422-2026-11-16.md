# T011 — HTTP high-degree neighbor limit handling

This stacked change depends on PR #91 (commit a771a08da053e3591ae92cd923178b8d11e95c88).
The legacy API endpoint now catches the specific full-list overflow InvalidOperationException
and emits a sanitized 422 with advice to use the existing paginated endpoint.
A dedicated integration test persists 10,001 valid incident edges, verifies 422,
checks response does not disclose the file path, and confirms paginated fallback 200.

This is not proof of authorization, bounded full graph loads, nor end-to-end performance.
The MCP SymbolContext still uses the legacy full-list query and needs an explicit
consumer-facing error policy before declaring this entire surface complete.
Human review and hosted CI required. No automatic merge.
